# Common Pitfalls

- **Writing the DSL as if it were Ant XML.** It is not — it is MPS nodes. Author via projectional editing or `mps_mcp_*` JSON tools, never by hand-editing the `.mps` file.
- **Forgetting `internalBaseDirectory`.** All relative paths are relative to this. Mis-setting it makes every source path wrong.
- **Declaring a module in `parts` and expecting it to appear in the output.** It won't — layout entries are what package things. If you don't reference a module in a `BuildLayout_CompileOutputOf` / `BuildMpsLayout_ModuleJars` / `BuildMpsLayout_Plugin` / group, it's not packaged.
- **Mis-syncing module dependencies.** MPS module dependencies (in `.mpl`) and build-script module dependencies (`BuildMps_ExtractedModuleDependency`) must match. Run **Reload Modules From Disk** (or the **Load required information from file** quick fix) after every `.mpl` change.
- **Missing transitive members in a `BuildMps_Group`.** All dependency-closure languages must be in the group or in a previously-declared group the plugin includes.
- **Not adding the MPS core plugin as a plugin dependency.** Every `BuildMps_IdeaPlugin` that contains languages needs `jetbrains.mps.core` or `com.intellij.modules.mps` in its `dependencies`.
- **Forgetting that `ant build` doesn't regenerate languages.** Make your languages in MPS first, or run `ant -f <fileName> generate build`. `useMakeTask` (*Execute a complete MPS make task*) does not change that: it makes the `generate` target run `<mps.make>` and skips `javac` in `build`, see `references/plugins-and-macros.md`.
- **Missing artifacts location on the command line.** Running the generated `build.xml` outside MPS needs `-Dartifacts.mps=…` (or the macro, e.g. `-Dmps_home=…`) pointing at an MPS installation.
- **Setting `compiler = IntelliJ` without an `idea_home` macro.** The IntelliJ compiler (`javac2`) needs a folder macro named exactly `idea_home`, pointing at an MPS installation; otherwise leave `compiler` empty (Ant's javac). Always set `javaLevel` explicitly.
- **"No such path in local layout" on MAKE** (full text: ``cannot build relative path to `X.jar': No such path in local layout``). A module's descriptor references a library jar (Reload adds a `BuildMps_ModuleDependencyJar`), but the layout does not contain it. The root check does not catch this. Add the jar inside the plugin's layout entry: `BuildMpsLayout_Plugin` → `children` → `folder lib { file <path to X.jar> }`.
- **Concept icons missing at runtime.** `copyResources` on `BuildSource_JavaOptions` is false, so the icons generated into `source_gen` are not packaged. Set it to `true`; see `references/java-parts.md`.
- **`AssertionError: bad file: <base directory>` from `[mps.make]` when the `generate` target starts.** A module declaration has an empty `path`, which the `<mps.make>` task (`useMakeTask = true`) lists as `<module file="${basedir}" />`. It is usually a `BuildMps_Generator` created from a JSON blueprint: the module node factory gives it an empty `path`, and the check and MAKE accept it. Delete that `path` child, or delete the generator declaration and apply Reload Modules From Disk again; then make the build solution again. See `references/mps-modules.md`.
- **"… should be extracted into build script" errors after Reload Modules From Disk.** The first pass only named the new modules; apply the intention again.
- **"Empty enumeration property" on a `BuildMps_Solution` (MCP check only).** `sourcesKind` has no stored default. MPS builds an empty value as `sources`, but the MCP checker flags it; set it to `sources`.
- **"mps_home macro should point to the unzipped generic MPS distribution".** The `mps_home` macro has no `defaultPath`; see `references/plugins-and-macros.md`.
- **Hand-editing the generated `build.xml`.** Anything you change there is lost on next generation. Modify the `.mps` source instead.
