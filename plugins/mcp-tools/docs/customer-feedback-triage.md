## 5. Upstream Platform & IDE Escalation Briefs

The following five non-`mcp-tools` platform/IDE issues were isolated from customer field reports and verified to originate outside `plugins/mcp-tools`:

1. **`CF-058` — Wayland Clipboard Deadlock During In-Process Test Setup (`JBR` / `MPS`)**
   - **Source**: `mps-gotchas.md` `#40` (`L452–L469`), `#52` (`L602–L611`).
   - **Environment**: Linux Wayland, MPS `2026.1.2`, JBR `25.0.4.1`.
   - **Mechanism**: `BaseTransformationTest.clearSystemClipboard` runs on the JUnit test thread and calls `SunClipboard.setContents` -> `WLClipboard.setContentsNative` while `AWT-EventQueue-0` handles `WLClipboard.handleClipboardOffer` -> `SunClipboard.lostOwnershipNow`, acquiring clipboard/AWT locks in opposite order and wedging the IDE process permanently.
   - **Recommended Upstream Action**: File against `JBR` (`WLClipboard` lock ordering) and `MPS` (`BaseTransformationTest.clearSystemClipboard` — skip system clipboard clearing in headless/automated test runs or guard under Wayland).

2. **`CF-059` — O(N²) `AnonymousClass` Index Walk in BaseLanguage TextGen (`MPS`)**
   - **Source**: `mps-gotchas.md` `#18` (`L208–L224`).
   - **Mechanism**: When `TextGenSupport.needPositions()` is active (`trace.info` generation), `AnonymousClass_TextGen` invokes `AnonymousClass.getJavaName` -> `Classifier.getIndexInContainingClass`, which repeatedly traverses ancestor/descendant trees for every anonymous class in large generated `_EditorBuilder_a.java` files (~94% of TextGen CPU samples in a 50 s editor build).
   - **Recommended Upstream Action**: File against `MPS` BaseLanguage TextGen/Behavior to memoize per-classifier anonymous-class indices during a TextGen pass.

3. **`CF-060` — `execute_run_configuration` 10 KB Truncation / Missing `TEST_FAILURE_BEGIN` & `execute_terminal_command` Wedging (`IDEA` Platform MCP)**
   - **Source**: `mps-gotchas.md` `#64`, `#82`, `#101`, `#107`, `#110`, `#111`, `#115`; `mps-mcp-recipes.md` `R1`.
   - **Mechanism**: Platform MCP's `execute_run_configuration` caps `structuredContent.output` at ~10 KB (`<truncated>`) without a tail summary and occasionally drops `TEST_FAILURE_BEGIN` markers even when `exitCode > 0`; `execute_terminal_command` can stop responding across a session while coroutine-based MCP tools remain healthy.
   - **Recommended Upstream Action**: File against `IDEA` MCP server (`com.intellij.mcpserver`) to surface structured JUnit failure summaries alongside `fullOutputPath` and isolate wedged terminal sessions.

4. **`CF-061` — JUnit Run Configurations Disappearing Across Module Rebuilds / Reloads (`MPS` Execution)**
   - **Source**: `mps-gotchas.md` `#57`, `#62`, `#75`, `#87`, `#126`, `#148`; `mps-mcp-recipes.md` `R1`.
   - **Mechanism**: `MPSRunConfigurationMcpToolset.registerJUnit` (`MPSRunConfigurationMcpToolset.kt:778-783`) registers non-temporary configurations via `RunManager.addConfiguration(settings)`, but rebuilding/reloading the target test or language module can cause MPS JUnit configuration listeners to invalidate or drop unsaved entries from `get_run_configurations`.
   - **Recommended Upstream Action**: File against `MPS` Execution (`jetbrains.mps.baseLanguage.unitTest.execution`) to audit `RunManager` retention across `ClassLoaderManager` reloads (and document idempotent `mps_mcp_create_run_configuration` refresh in `mps-run-configurations`).

5. **`CF-062` — Live `java_classes` Stub Churn, Editor Hot-Reload Focus State & Pre-`MAKE` Link Retargeting (`MPS` Core)**
   - **Source**: `mps-gotchas.md` `#150`, `#165`, `#167`, `#168`, `#170`.
   - **Mechanism**: Repeated live additions/removals of `java_classes` JAR `modelRoot`s followed by `MAKE` can trigger modal reload prompts or deadlocks, and editor hot-reload can leave stale Swing focus listeners. (Note on `#150`: `TargetConceptChecker2` in `CheckerRegistry` already checks `!SConceptOperations.isSuperConceptOf(link.getTargetConcept(), childConcept)` once the language's structure descriptor is rebuilt via `MAKE`; silence before `MAKE` is `CF-015` / `D80` runtime descriptor staleness.)
   - **Recommended Upstream Action**: File against `MPS` Core (`JavaClassStubsModelRoot` reload lifecycle and editor hot-reload focus cleanup; verify `TargetConceptChecker2` runs in the affected checker path post-`MAKE`).
