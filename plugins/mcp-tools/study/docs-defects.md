# Documentation defects found during the skill-script automation study

Kept separately from the hotspot work (study section 8) so fixes are not blocked on scripting.
Each entry: where, what is wrong, evidence (run id + step, or commit), status.

Closed, fixed, rejected, and out-of-scope entries were moved to [`docs-defects-archive.md`](docs-defects-archive.md) on 2026-09-22. This file holds only issues still to be handled.

| id | where | what is wrong | evidence | status |
|---|-------|--------------|----------|--------|
| D43 | tool descriptions / `mps-mcp-workflow` reference formats | Module and model parameters use six conventions across sibling tools — `conceptRef`, `conceptRefs`, `languageRefs`, `enumerationRef`, `modelReference`, `moduleName` — and `create_model`'s `moduleName` in fact accepts a module *reference*, the exact value the agent tried to pass as `moduleReference`. Five of nine retries in round 8 were this. Tools that validate in-body return a near-miss-aware message and cost one turn; `insert_root_node_from_json` (`modelReference`) and `create_model` (`moduleName`) declare the parameter required in the signature, so the platform answers with a generic "No argument is passed for required parameter 'x'" that never names the argument it dropped — `S2:75` then spent a `ToolSearch` to recover. | `S1-sonnet-1:103,109`; `S2-sonnet-1:68,75-77` (round 8) | open — remedy is **S**, not docs: make the two parameters optional and validate in-body like `get_concept_details`; see `HOTSPOT_REPORT_round8.md` §4 |
| D44 | `mps-aspect-*` `references/*.md` | Every large reference file opens with a `## Contents / when to read what` block, and agents do not use it: they run `grep -n '^## '` to rebuild the same index, then a ranged `Read`. The block costs bytes in each read and saves no turn. 45 of S1's 131 tool calls (34 %) were skill navigation. | `S1-sonnet-1:27-33` (round 8) | open — **D/T**: put line ranges in the Contents block, or hoist each file's section list into the owning `SKILL.md`; see `HOTSPOT_REPORT_round8.md` §3 |
| D45 | `parse_java_and_insert` | `featureKind: STATEMENTS` into a `*Function` `body` role fails because the role expects a `StatementList`; the caller must insert the `StatementList` first and re-target its `statement` role. The error text says so clearly, but the two-step dance is mechanical. | `S2-sonnet-1:53-55` (round 8) | open — **S**: auto-wrap when the target role requires a `StatementList` |
| D46 | no tool exposes a language's own `version` int (the field that gates `MigrationScript.fromVersion` applicability, distinct from consumer `languageVersions` stamps); `mps_mcp_update_module` only supports RENAME/CHANGE_VIRTUAL_FOLDER/DELETE, and no structure-aspect operation covers it either. `mps-aspect-migrations` skill only documents the UI path (Language Properties dialog / "New Migration Script" wizard action). The worker attempted the console-reflection workaround (`ModuleRepositoryFacade` → cast to `jetbrains.mps.smodel.Language` → `setLanguageVersion`/`save`), but it doesn't resolve directly in the console (ephemeral `TempModule` has no dependency on `MPS.Core`, and no `mps_mcp_module_dependency`/`model_dependency` call can wire one in because the console module isn't addressable); routing the reflection call through a real project module instead compiled and validated clean but then silently no-op'd when run via `mps_mcp_run_console_command` (`{"executed":true}`, no console-history entry, version stays 0) — a classpath/compile gap between the console's temp module and real project modules with no MCP-visible signal. The task's own "stop and explain if blocked" instruction was the only thing that ended an otherwise open-ended retry loop (5 `run_console_command`/`get_console_history` round trips, 3 `sleep` polls, 18 skill-doc greps hunting for a documented mechanism); first-ever S4 measurement (round 9), task **FAILED** on this alone — structure refactor (criterion 1) was otherwise clean. | `S4-sonnet-1:29-35` (skill search), `S4-sonnet-1:96-127` (console attempts + stop); `HOTSPOT_REPORT_round9.md` | open — **S**: add a `BUMP_VERSION` (or similar) operation to `mps_mcp_update_module` / `mps_mcp_alter_structure` for the language's own version int; **D** in the meantime: document the gap and that the console workaround is known not to work, so a worker stops after one probe instead of ~30 |
