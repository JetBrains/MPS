| D47 | `mps_mcp_insert_root_node_from_json` (`AbstractNodeOps.kt:172-173`) | **Node factories are run without a target model on the JSON-blueprint insert path, and whatever they build is then deleted.** `mps_mcp_create_root_node` uses `SNodeFactoryOperations.createNewRootNode(model, concept, null)` (`JetBrainsMPSRootNodeMcpToolset.kt:433`), so `NodeFactoryManager.setupNode` — which walks super-concepts *and* implemented interfaces — invokes each `NodeFactory.setup(node, sample, enclosing, index, model)` with a real `model`. `insert_root_node_from_json` instead calls the 2-arg `SNodeFactoryOperations.createNewNode(sConcept, null)` overload, which forwards `model = null` and `enclosingNode = null`, and the very next line (`AbstractNodeOps.kt:173`) deletes every child the factory produced. Regression tests: `NodeFactoryOnBlueprintPathIntegrationTest`. **MPS side** (the other half of "stop swallowing factory exceptions"): `DSLDescriptor.initializeInstance` in `jetbrains.mps.baseLanguage.lightweightdsl`'s behavior aspect ended in `catch (Exception e) { e.printStackTrace(); }`, which sits *inside* the factory and so swallowed the failure before the new MCP-side try/catch could ever see it — for the migration case specifically, a broken initializer still produced a clean success envelope with no warning.
