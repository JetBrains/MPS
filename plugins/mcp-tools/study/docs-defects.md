# Documentation defects found during the skill-script automation study

Kept separately from the hotspot work (study section 8) so fixes are not blocked on scripting.
Each entry: where, what is wrong, evidence (run id + step, or commit), status.

| # | Where | Defect | Evidence | Status |
|---|-------|--------|----------|--------|
| D1 | `mps-mcp-workflow/references/mcp-tools-index.md` | Study 1.2(4) claims the index omits `search_root_node_by_name`, `parse_java_and_insert`, `create_run_configuration`. | All three present as of commit fc28c2636dce (verified 2026-09-15). | already fixed |
| D2 | `test_scenarios/StateChartScenario.md` | Contains reporting requirements ("keep ongoing notes", "final report"), which study 6.2 forbids in worker prompts. | file header | not a worker prompt; use as fixture builder only |
| D3 | tool descriptions / `mps-node-editing` (file-path `childJson`) | On macOS the worker wrote its blueprint to `/tmp/...` and got `Input file path '/tmp/…' is not inside the system temp directory`. Neither the tool description nor the skill says the file must be under `java.io.tmpdir` (`$TMPDIR`, `/var/folders/...` on macOS), and the error does not name the accepted directory. | S1-opus-1 (first error result, ~step 40) | provisional — confirm in transcript, then fix wording |
| D4 | `mps_mcp_get_concept_details` (and likely other name-resolving tools) | `unresolved[].suggestions` for a plain concept name are taken from the shared module repository, so with a same-named language in another open project the suggestions point into that other project (conceptReference with the foreign language UUID). Not a docs defect strictly — a tool-behaviour issue: suggestions should be scoped to the selected project or be labelled with their project. | S1-sonnet-1, get_concept_details result containing `c:d10ad89a-…` (opus project) | open — report to tool owners |
| D5 | `mps_mcp_print_node` JSON output / `analysis-tools.md` | An enum property holding the enumeration's *default* literal is printed as `"value": ""` (MPS stores nothing for the default). The evaluator initially read 13 recipes as missing `difficulty`; the plain-text projection shows `easy`. The output schema doc should state that an empty enum value means "default literal" (or the printer should emit the default's name with a flag). | S3-opus-1 evaluation; fixture recipe Crepes shows the same | open |
| D6 | `mps_mcp_create_module` result / `mps-mcp-workflow` | Both S1 workers tried to create `mcp.study.recipes.structure` after `create_module` had already created the aspect models (`No suitable model root found … to create model`). The result should list the models it created; the skill should say a new language comes with structure/editor/… models. | S1-opus-1, S1-sonnet-1 first error envelope | open |
| D7 | `mps_mcp_check_root_node_problems` (model reference) | Workers re-check every root after a clean model-level result (S3-opus-1: 50 calls). The envelope should state coverage, e.g. `rootsChecked: 48`, so the model-level answer is visibly exhaustive. | S3-opus-1 steps ~35–95 | open — tool envelope |
| D8 | `mps_mcp_get_project_structure`, `mps_mcp_print_node` | Always return a temp-file path, even for tiny payloads, forcing a second call to read it (32/23/25/4 envelopes per run). Inline small results; add `fields`/`summary` options for the large ones. | all runs; chains #1, #6, #9 | open — tool behaviour |
| D9 | `mps_mcp_print_node` `format` / `analysis-tools.md` | Allowed literals (`JSON`, `HTML`, `PLAIN TEXT`) are not listed; the space-containing literal is unguessable ("text" rejected). | S1-sonnet-1:110-111 | open |
| D10 | `mps_mcp_update_node` `childJson` vs `insert_root_node_from_json` | Top-level array accepted by the insert tool but rejected by `update_node` (`Expected JsonObject but was JsonArray`); asymmetry undocumented, forced 3 single-child calls. | S1-sonnet-1:129-132 | open |
| D11 | file-path `childJson` error text | "Write the JSON to a temp file (e.g. via File.createTempFile)" is a Java hint given to a shell agent; should name `$TMPDIR`. Worker wrote itself a memory note about it. | S1-opus-1:16-18, :173 | open (with D3) |
| D12 | `get_project_structure includeNodes` dump | Properties holding their default value are omitted from the dump, so verification scripts report false "missing" values (`KeyError: 'difficulty'`). Same root cause as D5. | S3-opus-1:28-33, :97 | open |
